# rlm-tools-bsl — tool catalog

Intent-first, token-efficient search and navigation backend for 1C BSL repositories.
Upstream: <https://github.com/Dach-Coin/rlm-tools-bsl>.
Last verified against upstream release `v1.34.0` and `master` on 2026-09-04.

`rlm-tools-bsl` does not expose one MCP tool per 1C operation. It exposes a small session API and a broad sandbox helper set; inside `rlm_execute`, the agent runs Python code that calls helpers for BSL files, metadata XML, forms, references, call graphs, data paths, object profiles, full-text search, extension overrides, and coverage/provenance checks. Prefer this server over raw agent-side `Grep` / `rg` and direct file reads whenever a task touches 1C source: it keeps large file bodies on the server and returns only compact `print()` output.

> Load this file only if the `rlm-tools-bsl` server is actually available in the current session.

## Read order for agents

Use this file in layers:

1. For ordinary repository search, read `Top-level MCP tools` -> `Session discipline` -> `Sandbox helper map`.
2. For subsystem/configuration reports, audits, and specifications, also apply `Agent analysis method`.
3. For migration from the retired indexed metadata server, use `Replacement map from the retired server` only after the normal RLM helper choice is clear.

Do not treat every section as a separate workflow. `Session discipline` is the default workflow; later sections add routing details, report-only gates, or migration aliases.

## Session discipline

1. Before the first `rlm_start` in a 1C repository, call `rlm_projects(action="list")`.
2. If the current workspace path is inside a registered project path, or the user mentions a registered project name, start with `rlm_start(query=..., project="<name>")`, not with `path`.
3. After `rlm_start`, verify `index.loaded`. If `index.loaded=false` and a matching registered project exists, immediately call `rlm_end` and restart with `project="<name>"`.
4. Do not proceed with filesystem fallback unless no matching registered project/index exists or the user explicitly requested path-based fallback.
5. Read the `rlm_start` response before acting: check `source_support`, `effective_effort`, `limits`, `warnings`, `extension_context`, `detected_custom_prefixes`, and `index.index_status` (`ok` / `stale_age` / `stale_content` / `missing` / `incomplete`). `source_support="supported"` means a CF / EDT layout was recognized. `foreign_with_bsl` means best-effort BSL-only work: metadata/object helpers can be unreliable, empty metadata results are not proof of absence, and conclusions must state the format limitation. `foreign_no_bsl` means generic mode: BSL helpers are not loaded, and `available_functions` contains only file / grep helpers plus `llm_query` when configured. `rlm_start.index` already carries `builder_version`, feature flags, and counts, so a separate startup `get_index_info()` call is usually unnecessary. If the index is missing/stale/incomplete or a helper returns `partial=True`, do not present partial helper output as complete. When helper output includes coverage/provenance fields, read `source`, `owner`, `extensions_included`, `total_exact`, `index_coverage`, `truncated`, and `has_more`; do not use legacy `scope` as a completeness proof. If `extension_context.nearby_extensions_truncated=true`, treat `nearby_extensions` as a top-N hint only and call `detect_extensions()` / `get_overrides()` when complete extension facts are needed.
6. In default slim strategy mode, call `rlm_help(...)` before non-trivial `rlm_execute` calls. Choose one route from `rlm_help routing`: `topic` for a business recipe, `helpers` for exact helper signatures, `category` for a helper list, or `section` for workflow / disambiguation / performance / batching / IO / critical / coverage guidance.
7. Batch operations inside one `rlm_execute`: search candidates, read the top files/procedures, compute a summary, then `print()` only the useful result. Prefer aggregate helpers (`get_object_profile`, `get_object_modules`) before assembling the same overview manually. Use list overloads where available (`read_procedure`, `find_callers_context`, `find_enum_values`). Variables persist between calls; reuse assigned results instead of repeating identical helper calls. If `rlm_execute` returns `efficiency_hints`, treat them as actionable guidance for later calls. In particular, `list_truncated:<helper>` means a list may be capped even though the helper itself returned a plain list; raise its `limit` or use the matching `count_only` / grouped route before calculating totals. If `sandbox_state.status="terminated"` and `state_lost=true`, discard assumptions about saved variables and caches; the next execute starts a clean worker generation and reports `sandbox_state.status="restarted"`.
8. Never run broad agent-side `Grep` / `rg` over `path='.'` or whole top-level directories on large 1C configurations. Prefer metadata/code helpers, `find_module` + targeted reads, and RLM full-text helpers (`git_search`, then `safe_grep` / `grep_read` on narrowed paths) before leaving the server.
9. End with `rlm_end(session_id)` unless the parent explicitly needs to continue the same session.

## Agent analysis method

Upstream `docs/AGENT_INSTRUCTIONS.md` defines a reporting discipline for agents that analyze a 1C configuration through `rlm-tools-bsl`. Apply this block when the task asks for a subsystem/configuration analysis, specification, audit, or other report where completeness matters.

Do not apply the hard gates below to a quick lookup such as "find this procedure" or "where is this attribute used". Quick lookups still follow `Session discipline`.

Base rule: facts come from data, not from memory or object names. Any claim about object composition, counts, attribute types, links, or business logic must be backed by helper output that actually read the relevant source. If the helper did not read it, treat it as unknown.

Two hard gates for subsystem-composition reports:

1. Composition and object counts come only from raw subsystem XML `Content` (`<xr:Item>` entries). Summary helpers such as `analyze_subsystem` may be used to locate the subsystem file, but not as the authoritative source of the object list or counts.
2. The last substantive `rlm_execute` before delivery must re-read `Content`, count `M` programmatically, compare it with the report total and the sum by object type, and print `СВЕРКА ОК: итог = сумма_по_типам = M = N`. If the numbers differ, fix the report and repeat the check.

Report-specific operational rules from the upstream agent instructions:

- Follow `Session discipline` for `rlm_start`, `rlm_help`, batching, and final `rlm_end`; for reports, use `effort="high"` unless the task is explicitly narrow.
- Use sandbox helpers as the source for 1C project data. Do not replace them with agent-side file reads or raw `Grep` / `rg` over large source files; that defeats the token-saving purpose of the server. Saving the final report is the normal file-tool exception.
- Check `rlm_start.index` at the start of analytic work. It carries `index_status`, `builder_version`, feature flags, and table counts; call `get_index_info()` only when you need an explicit in-session refresh or diagnostics beyond startup data. If the index is absent, stale, incomplete, or a helper returns `partial=True`, do not present partial data as complete; state the limitation and consider `rlm_index(action="build"|"update")` when the user can provide the project password.
- Treat a helper miss as inconclusive until you have done a broader search. Escalate from structural helpers to `search(...)` and then `git_search(...)` for GUIDs, user messages, query fragments, form/right/DCS XML attributes, and technical literals before writing "not found".
- For key logic, read procedure bodies, not only signatures or names. Posting and movements may be implemented through common modules, event subscriptions, or register-writer helpers rather than directly in the object module.
- Keep the report slice targeted: filter event subscriptions, movements, references, and counts to the subsystem/custom prefixes where possible. Do not report configuration-wide noise as subsystem-specific evidence.
- Separate objects included in subsystem `Content` from related objects that are merely used by attributes, queries, forms, or movements. Put related-but-not-included objects in a separate section.
- Use exact metadata types for attributes, dimensions, resources, and columns (`CatalogRef.X`, `DocumentRef.X`, `Number`, `Boolean`, `EnumRef.X`, etc.).

Recommended workflow for a full subsystem/configuration report:

1. `rlm_start(..., effort="high")`, inspect warnings and `rlm_start.index` (`index_status`, `builder_version`, feature flags/counts).
2. `rlm_help` for workflow and task-specific recipes.
3. Locate the subsystem XML, read raw `Content`, and compute composition counts by type.
4. For every object from `Content`, use `get_object_profile(name)` as the first compact overview when applicable, then collect missing structure, tabular sections, dimensions/resources, forms, and relevant flags with exact types.
5. Collect applicable surroundings: roles, functional options, subscriptions, based-on links, print forms, register writers/movements, and integrations.
6. Read key procedure bodies and follow actual execution through calls/subscriptions/common modules.
7. Run the final programmatic reconciliation check and self-review before delivery.
8. Call `rlm_end` after the analysis is complete.

## `rlm_help` routing

`rlm_help` returns JSON `{mode, result, warnings}` and has priority-ordered dispatch:

| Input | Result |
|---|---|
| no arguments | Menu of topics, categories, sections, and helper count. |
| `topic="..."` | Compact or full recipe for a business domain / alias. Current notable topics include rights, posting, forms, references, integrations, reachability, and data path analysis. |
| `section="disambiguation"` | Structured helper-choice rules; pass `helpers=["a", "b"]` to narrow to a specific pair. |
| `section="workflow" / "performance" / "batching" / "io" / "critical" / "coverage"` | Raw strategy section. Use `coverage` to interpret `source`, `owner`, `extensions_included`, `total_exact`, `partial`, `index_coverage`, `truncated` / `has_more`, and why `scope` is not a completeness signal. |
| `helpers=["name1", "name2"]` | Exact signatures, keywords, and recipes for helpers. |
| `category="discovery" / "code" / "xml" / "composite" / "business" / "extension" / "navigation"` | One-line helper list for the category. |

## Sandbox helper map

The complete helper list is returned by `rlm_start.available_functions`; detailed helper docs are available through `rlm_help(helpers=[...])`. Use this table to choose helpers for new RLM work:

| Need | RLM helper(s) inside `rlm_execute` |
|---|---|
| Broad search by object / method / attribute / region | `search(query, scope="all", limit=...)`; refine with `search_objects(query="", limit=50, count_only=False)`, `search_methods`, `search_regions`, `search_module_headers`, `find_attributes`, `find_predefined`. Use `count_only=True` on `search_objects`, `search_regions`, or `search_module_headers` when you need totals instead of a capped list; use `search_regions(group_by="name"|"category")` for top groups. |
| Find metadata objects by category | `find_by_type(meta_type, name="", limit=50, count_only=False)`, or the keyword alias `find_by_type(category="...", ...)`, for folders/types; do not pass both `meta_type` and `category`. `count_only=True` returns module-row and unique-object counters. Use `search_objects(query)` for technical name or synonym. |
| Full object structure / overview | `get_object_profile(name, sections=None, include_flow=False, include_code_usages=False, limit=20)` for a compact one-call overview (structure, modules, registers, subscriptions, roles, functional options); `get_object_full_structure(name)` for metadata-side structure; `parse_object_xml(path)` when you need live XML completeness or index freshness is uncertain. |
| Find modules of an object | `get_object_modules(name, include_methods=False)` for all modules plus outlines and totals in one call; otherwise `find_module(name="", module_type="", category="", limit=50)`, then `get_module_outline(path, include_methods=False)`, `extract_procedures(path)`, `find_exports(path)`, `code_metrics(path)`, or `read_file(path)` when the exact file is already narrowed. |
| Find a routine / read its body | `find_definition(name, module_hint="", limit=50)` for go-to-definition. It can use the index or live BSL parsing, returns all candidates, and exposes completeness through `partial` / `_meta.total_exact`; use `module_hint` (`rel_path`, `Документ.X` / `Document.X`, or object name) for common 1C names such as `ОбработкаПроведения` / `ПередЗаписью`. `search_methods(query)` is still the indexed substring route. `read_procedure(path, [names...])` batches several procedure bodies from one module. |
| Extract query text from BSL | `extract_queries(path)` for static query literals in a module. It recognizes ordinary `Запрос.Текст = "..."`, assignments where the literal starts on the next line, and constructors such as `Новый Запрос("...")` / `New Query("...")`; dynamic expressions and concatenated query assembly still need body reading. |
| Module outline before reading bodies | `get_module_outline(path_or_object, include_methods=True/False, no_live=False)` for `#Область` tree, method/export counts, orphan methods, and line ranges. Use it as the first hop for 5K-15K line modules; with an object name, inspect `_meta.resolved_from_name`, `candidates`, and `ambiguous`. |
| Full-text code or XML search | `git_search(pattern, path="", file_types="", regex=False, ignore_case=False, mode="lines", max_results=..., exclude_path="")` for git-backed sources and technical literals. Use `exclude_path="Forms,Templates"` or similar literal names to suppress noisy zones. `git_search` follows Git ignore/binary rules; use narrowed `safe_grep(pattern, name_hint, max_files)` when candidate BSL files may be ignored or marked binary. `safe_grep` also returns a dict with `results` / `returned` / `truncated` and coverage counters, but argument errors remain `ValueError` rather than an `error` field. `grep` / `safe_grep` reject catastrophic-backtracking regex patterns with `ValueError`. Use `grep_read` only on narrowed paths. Raw agent-side `Grep` / `rg` is the last fallback, after RLM helpers are insufficient. |

| Call-path reachability | `find_path(from_name, to_name, max_depth=4, from_hint="", to_hint="", include_triggers=False)` for a forward path through the BSL call graph. | Metadata usages, references, and data paths | `find_references_to_object(object_ref, kinds=None, limit=..., include_code=False)` for declarative metadata references; on a live route inspect `_meta.unsupported_kinds` before treating an empty result as absence. `find_code_usages(object_ref, kind=None, limit=...)` covers code usages; inspect `_meta.kind_filter_applied` because a live fallback returns `unknown` candidates instead of applying `kind`. `find_data_path(from_object, to_object, max_depth=4, kinds=None)` finds an N-hop metadata-reference path. ## Helper and runtime notes

- `rlm_start` supports server-side `effort="auto"`: the server chooses `medium` for simple lookups and `high` for multi-aspect analysis. Precedence is `RLM_FORCE_EFFORT` > explicit `effort` > `auto`; numeric limits are explicit `max_execute_calls` / `max_llm_calls` > `RLM_MAX_EXECUTE_CALLS` / `RLM_MAX_LLM_CALLS` > the effort preset. Read `effective_effort` and `limits`; a `== SERVER LIMIT OVERRIDE ==` strategy banner means server env changed the numeric limits. Full subsystem/configuration reports still use explicit `effort="high"`.
- `rlm_start.source_support` separates "recognized 1C layout" from "unknown layout": supported CF/EDT sources report `supported`; foreign trees with `.bsl` report `foreign_with_bsl` and stay usable only for path/text-based BSL analysis; foreign trees without `.bsl` report `foreign_no_bsl` and expose only generic file helpers. Do not treat empty metadata helper output in a foreign mode as evidence that a 1C object is absent.
- On extension-heavy main configurations, agent-facing extension lists can be capped through `RLM_EXT_LIST_CAP` (default `20`). When `nearby_extensions_truncated=true`, use `detect_extensions()` for the full list and `get_overrides()` / `find_ext_overrides()` for details. `RLM_EXT_OVERRIDE_DETAIL` controls how many named override lines are included in the startup strategy; default `0` keeps only counters and on-demand pointers.
- `rlm_start.index` carries startup discovery data: stable `index_status`, `builder_version`, `has_*` feature flags, and row counts for indexed tables. Use this before spending a separate `get_index_info()` call.
- Index freshness is part of the server contract: `rlm_start.index.builder_version` and startup warnings say whether an index rebuild or update is needed. During an in-place rebuild, `index_status="incomplete"` means new sessions must not treat the index as usable until the build finishes.
- `rlm_index(action="build")` through MCP refuses a source tree whose layout is not recognized as CF or EDT. If a human intentionally wants an incomplete index for a foreign tree with `.bsl`, they must run the CLI command suggested by the server with `--allow-unsupported-format`; do not try to force it through MCP.
- The default process sandbox runs one worker per session, physically separates concurrent stdout, and enforces hard wall-clock termination of the worker tree. Read `rlm_start.limits.sandbox_mode`; `inline` is a diagnostic fallback without guaranteed hard-kill behavior. A terminated worker loses session variables/caches but not execute/LLM quotas, returns partial stdout when available, and restarts lazily on the next `rlm_execute`.
- Size the server for process workers: `RLM_SANDBOX_MEMORY_MB` is a per-worker ceiling (default `1024`), while aggregate pressure is primarily controlled by `RLM_MAX_SESSIONS`. Other guards cap worker startup, shutdown, IPC frames, submitted code, and, on Windows, child-process count; invalid explicit sandbox settings fail server startup instead of silently falling back to inline mode.
- Register movement helpers and the `get_object_profile` register section apply live posting analysis over indexed facts. They filter collection methods such as `Движения.Записать()` / `Движения.Очистить()`, recognize `Движения.X`, `RegisterRecords.X`, and record-set creation through `Регистры<Тип>.<Имя>.СоздатьНаборЗаписей()` in manager modules, include readable neighboring CFE modules, honor `Posting=Deny` and replacing CFE handlers, and expose delegated posting through `posting_handler_present` plus an executable `hint`. Main indexed rows can still be stale after code changes, so verify critical movement facts against the live module.
- `find_register_writers` intentionally returns static candidates and marks them `runtime_filtered=false`; it does not apply CFE replacement or `Posting=Deny`. Run `find_register_movements(document)` for each candidate before describing it as an active runtime writer.
- `find_based_on_documents` uses exact-first document resolution and augments code-derived links with indexed `<BasedOn>` metadata, including catalog and other typed sources. Metadata rows carry canonical `ref` / `category` / `via="metadata"` fields. Treat `partial=true` or `_meta.reason` as an incomplete answer, especially when metadata-reference tables are unavailable.
- `find_functional_options(...)` returns `xml_total`, `code_total`, and their sum `total`; only `xml_total` answers the exact metadata-membership count because code matches are substring-based. `limit=N` paginates XML and code buckets independently; pass it by name because the second positional argument is `include_code`. Read `_meta.code_scope`: a non-empty object scans that object's modules, not the whole configuration. For an empty-object overview, `partial=true` with `_meta.reason="code_scan_budget"` means totals cover all XML plus only the reported code scan slice.
- `find_event_subscriptions` performs exact/category-aware matching for qualified object names, includes catch-all subscriptions with empty source types, and labels object-scoped rows with `scope` (`exact`, `partial`, or `universal`). The `get_object_profile` subscriptions section includes exact and universal counts.
- `get_object_profile` is the preferred first hop for a compact object overview. Its roles section counts both object-level grants and member-level grants such as commands, so use it for the first aggregate view; use `find_roles` or role XML reads when detailed permission rows are needed. `get_object_modules` is the code-side aggregate for modules and outlines; combine it with `get_object_full_structure` for metadata-side details.
- `rlm_execute` may return `efficiency_hints` such as batch, reuse-variable, read-files, or `redundant_get_index_info` guidance. Follow them in later calls; they are response metadata, not helper stdout. If `redundant_get_index_info` appears, use the already returned `rlm_start.index` data instead of spending an early extra `get_index_info()` call.
- Plain-list helpers can signal a possible cap through `efficiency_hints` with id `list_truncated:<helper>`. This applies to navigation/search lists such as `find_module`, `find_by_type`, `search_objects`, `search_methods`, `search_regions`, and `search_module_headers`; do not aggregate a capped page as if it were the full set.
- `search_regions` and `search_module_headers` use substring matching without stemming; retry with another inflection or a stable word root before concluding that nothing exists. The main `search_methods` index uses trigrams, so a query shorter than three characters does not search main-index rows and may return only live extension matches.
- `read_procedure`, `find_callers_context`, and `find_enum_values` accept list inputs for batching. Keep scalar calls for one-off reads, but pass lists when collecting several procedures/callers/enumerations in one module/task.
- `extract_queries(path)` is the cheap first pass for static query literals, including `Новый Запрос("...")` and next-line assignment forms. It deliberately does not reconstruct fully dynamic query assembly; for those cases read the owning procedure body.
- `search_regions(..., count_only=True)` and `search_module_headers(..., count_only=True)` are CFE-aware when extensions are present: non-empty queries can return `total_main`, `total_extensions`, and `scope="main_index+live_extensions"`. Use these counters instead of requesting full lists only to reconcile extension hits.
- Most helper `limit` / `offset` parameters now recover from invalid values by falling back to documented defaults instead of running unbounded scans or failing with raw SQL errors. `limit=0` remains valid; `None` means "unlimited" only where explicitly documented, such as `find_event_subscriptions` and `find_functional_options`.
- Sandbox error hints can suggest real helper names for guessed calls and print actual signatures for unsupported keyword arguments. Use those hints to self-correct, but still confirm unfamiliar helper signatures through `rlm_help(helpers=[...])`.
- The sandbox intentionally rejects common unsafe Python patterns, including dangerous dunder/frame introspection, `operator` imports, and attribute assignment/deletion. Use plain functions, `lambda`, dictionaries, and local variables in `rlm_execute` snippets.
- `find_definition(name, module_hint="", limit=50)` and `get_module_outline(path, include_methods=True)` are read-only helpers. They use existing index tables when available and degrade to live parsing where possible; no index rebuild is required solely because these helpers appeared. `get_module_outline` rejects paths outside the sandbox and extension roots instead of returning a structural result for an unreadable file.
- `find_path(...)`, `find_data_path(...)`, and `find_call_hierarchy(..., include_triggers=True)` depend on index freshness for trustworthy graph analysis. If the index is old, missing, or marked partial, report that limitation and verify critical findings with targeted reads / references. If `find_path` reports an ambiguous endpoint, rerun with the relevant `from_hint` / `to_hint`.
- `search_regions(query, count_only=True)` and `search_module_headers(query, count_only=True)` provide cheap counts when a full result list would be too noisy. `search_regions(group_by="name"|"category")` returns grouped top-N counters; use it instead of computing top regions from a truncated alphabetical list.
- `find_files(name)` is instant on index hits, but a zero-hit index result can fall back to filesystem scanning; this is useful for stale indexes but may be slower on large trees.
- `get_overrides()` returns deterministic pages plus `total`, `offset`, `returned`, `has_more`, `truncated`, `partial`, source, annotation/object/extension aggregates, and unique counts. Use server-provided aggregates instead of summarizing the capped slice; when `partial=true`, totals are lower bounds and `_meta.failed_extension_roots` identifies unread roots. Filter by object/method or use `find_ext_overrides()` for detailed extension rows. `get_overrides()` and `find_ext_overrides()` normalize extension row aliases such as `module_path` / `ext_module_path`, `line` / `ext_line`, and `module_type`; prefer the normalized keys but do not assume missing line data means an index defect.
- `parse_form(...).attributes[].types` is a list of type names. In `find_references_to_object`, `line` is the actual metadata-reference line for supported reference kinds (`attribute_type`, `owner`, `based_on`, `default_object_form`, `default_list_form`); `line=None` on other kinds is a declared contract, not necessarily an index defect.
- `git_search(..., exclude_path="Forms,Templates")` excludes literal file or directory names at any depth. Do not pass glob patterns to `exclude_path`; invalid elements should be treated as a helper error, not silently broadened.
- `rlm_index(action="build"|"update"|"drop")` is an MCP-side administrative action: it requires a registered project and the project password. When the tool returns `approval_required`, ask the user for the password; do not guess or reuse unrelated credentials. `info` / `drop` can inspect or remove an index even after the source directory was deleted by recovering the base path from index metadata; `drop` also removes the file cache when possible and may include `dropped_cache` in the response.
- Runtime logs: `RLM_LOG_EXECUTE_CODE` logs the Python code passed to `rlm_execute` into `server.log` by default, capped at 300 characters unless overridden; set it to `0` / `false` / `off` / `no` when helper calls may expose sensitive object names, query fragments, or parameters in logs. `RLM_LOG_RETENTION_DAYS` trims `server.log` on startup (default `20`; `0` or negative disables time-based trimming).
- PyPI installs constrain the MCP SDK dependency as `mcp[cli]>=1.26.0,<2`. If an old installation fails with `ModuleNotFoundError: No module named 'mcp.server.fastmcp'`, rerun the upstream install/update script so the resolver downgrades from incompatible `mcp` 2.x.
- When using `llm_query`, the default sub-LLM response cap is now 2048 tokens. Tune with `RLM_LLM_MAX_TOKENS`; for OpenAI-compatible providers only, `RLM_LLM_EXTRA_BODY` passes a JSON object as `extra_body` after dropping owned keys such as `model`, `messages`, `max_tokens`, and `stream`. Treat `[TRUNCATED]` as an incomplete answer, `[EMPTY]` as a diagnostic marker rather than "nothing found", and `[REFUSAL]` as a model refusal.

## No direct replacement

`rlm-tools-bsl` is an exploration server, not an XSD/XML validator and not a platform-reference server.

- For metadata XML validation use the `1c-metadata-manage` validators (`form-validate.ps1`, `meta-validate.ps1`, `role-validate.ps1`, `skd-validate.ps1`, `mxl-validate.ps1`, `cf-validate.ps1`, etc.) or the available XML-generation/validation skill for the active tool.
- For platform API/member discovery use `1c-syntax` (`search_syntax`, `get_function_info`, `suggest_completion`, `validate_syntax`) and, when needed, the live syntax-reference tools exposed by the environment.
- For 1C help / methodological documentation use `onec-buddy-mcp` (`search_1c_documentation`, `search_its` → `fetch_its`) or repository help files found through `git_search`.
